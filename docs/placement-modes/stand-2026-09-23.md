Notes.

- Trial 5 exercised the review-wave-1 fix: an unmounted DS directory is a
  failed probe (mount-point check), so the observation aged out instead
  of the MDS root filesystem being reported as DS capacity; DS 1 returned
  to `reason=NONE` 14 s after the remount.
- Trial 4: `fallocate -l 27T` reserved 27 TiB (29.7 TB), leaving 4.2 TB
  (12 %) rather than the 20 % aimed for; the observed 89 : 11 matches the
  12 : 98 weights (89.1 % expected). The reservation was removed; XFS
  released the space within a minute.
- `mds-admin config show` reaches the daemon on the address it binds
  (`cluster_bind_addr`, 192.168.65.223:50051), not on loopback — the
  deploy script now uses the node's own address; `--mds-port 50051` is
  needed because the CLI defaults to 9800.
- The stand is left on the legacy configuration (row 6) with the new
  binary; rollback to the pre-Stage-A binary is `pm-deploy.sh --rollback`.
- Not measured here: LAT-25 create-throughput budget (Stage C acceptance).
