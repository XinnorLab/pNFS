# Audit 2026-09-23 — findings and resolution

Codex audit of the connector at `474d6b7` (verdict NO-GO, findings
C-01…C-07). Every finding was verified against the code before it was
acted on; C-04 had already landed in `f58138d`. Resolution shipped in the
commit that adds this file. Tests named here live under `tests/`.

| # | Finding | Resolution | Tests |
|---|---|---|---|
| C-01 | The policy resolved references by id only; a schema-valid snapshot whose share pointed at another share's export, at a filesystem not containing its path, or at a record of the wrong kind still produced `VALID` allow. | `xinas_policy._check_share_graph` and the array loop prove the graph: reference kinds, export path = share path, filesystem mountpoint contains the path and is the most specific managed filesystem that does, DATA array `volume_path` = filesystem `source_device`, LOG / REALTIME arrays = `logdev=` / `rtdev=`, no `INTERNAL` log with a log device. Any contradiction → `UNKNOWN` / `GRAPH_INCONSISTENT`, each contradiction listed in `diagnostics.graph_inconsistent`. | `test_c01_*` (reference substitutions, volume/logdev mismatch, most-specific filesystem, internal log) |
| C-02 | Runtime validation was structural only; a `SUCCESS` record without `evidence_age_ms` / `observed_at` was dropped from the freshness check instead of failing it. | Every `SUCCESS` share/filesystem/export/service/array must carry both fields → otherwise `UNKNOWN` / `EVIDENCE_AGE_MISSING`. `validate_envelope` type-checks every record it will dereference, rejects duplicate share / resource ids, and applies the full `contracts/xinas-observations.schema.json` when `jsonschema` is installed (`python3-jsonschema`); the structural checks never depend on it. | `test_c02_*` in `test_policy.py` and `test_xinas_module.py` |
| C-03 | `uuid` / `incarnation` were interpolated into the capacity domain even when null; the xiRAID edition / version and the RAID level were not checked against the profile's compatibility; an empty `members` list read as healthy. | `FILESYSTEM_IDENTITY_MISSING` (no domain), `XIRAID_VERSION_UNSUPPORTED` (edition ≠ Classic or version ∉ 4.4.x), `RAID_LEVEL_UNSUPPORTED` (level ∉ 0/1/5/6/7/10/50/60/70/n+m in either spelling), `MEMBER_STATE_MISSING` for an empty list — all `UNKNOWN`. | `test_c03_*` |
| C-04 | The `/etc/exports` listing was accepted as effective access. | Landed in `f58138d`: `export_source_required: etab` by default; `EXPORT_SOURCE_NOT_EFFECTIVE` otherwise. | `test_export_source_etab_is_the_default_…` |
| C-05 | A binding without `expected_target_incarnation` accepted any incarnation; nothing guarded against a replayed or regressed source generation. | `validate-config` requires the pin on xinas bindings (`INCARNATION_REQUIRED`); the policy returns `UNKNOWN` / `INCARNATION_UNPINNED` if one slips through; the new `discover` subcommand prints every share's current incarnation to pin. `InstanceRuntime` ignores a snapshot whose `(server_epoch, source_generation)` is not newer than the last accepted one (`connector_source_replay_total`, `source_replay_ignored`); a new epoch resets the line. | `test_binding_without_expected_incarnation_is_unknown_not_trusted`, `test_discover_…`, `test_c05_regressed_generation_…`, `test_t18_same_source_snapshot_repeated_…` |
| C-06 | A hostname / netgroup rule was ignored whenever an IP rule already covered the network, although it may apply to hosts of that network and contradict the IP rule. | Any unsupported rule present in the export → `UNKNOWN` / `EXPORT_RULE_UNSUPPORTED`, regardless of IP coverage. | `test_c06_*` |
| C-07 | The bounded helper covered `collect` only (`evaluate` ran unbounded on the worker), and a new helper was started on every tick while the previous one still hung. | One helper per instance runs `collect` + `evaluate` inside the deadline; while it is alive the next tick is skipped with `COLLECT_IN_FLIGHT` (counted as stuck, retained lease); its late result is discarded. Plain `http://` sources are additionally refused outside `test_mode: true` (`INSECURE_HTTP_PRODUCTION`). | `test_c07_slow_evaluate_…`, `test_t22_hanging_collect_…`, `test_typed_errors[INSECURE_HTTP_PRODUCTION]` |

Not changed by the audit: the decision table itself (XMOD-06..10), the
hold-down and TTL semantics (CON-10..16), the batch contract
